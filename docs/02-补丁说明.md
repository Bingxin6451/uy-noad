# 补丁说明

三处改动，全部可脚本复现，不含任何设备或账号相关逻辑。

---

## P1 · 断根：删广告 Provider

Provider 是 Android 里唯一"进程一启动就执行"的组件，广告 SDK 靠它自动初始化，不需要 App 主动调用。

删掉的 10 个：

```
com.bytedance.sdk.openadsdk.multipro.TTMultiProvider
com.bytedance.sdk.djx.act.DJXProvider
com.bytedance.sdk.dp.act.DPProvider
com.bytedance.pangle.provider.MainProcessProviderProxy
ServerManager_bytelive / ServerManager_push / LiveServerManager
MainServerManager / DownloaderServerManager / ServerManager_downloader
```

**保留** `TTFileProvider` / `BdFileProvider` / `AdSdkFileProvider`——它们是 `FileProvider` 子类，业务下载与分享可能依赖，删了会 `ActivityNotFoundException`。

脚本：`patcher/patch_manifest.py`

---

## P2 · 短路开屏

`SplashActivity.e1()` 是开屏广告的入口：

```smali
# 改前
if-eqz v1, :cond_0        # 广告开关关闭 → 跳过广告
new-instance v0, Lcom/bytedance/sdk/commonsdk/biz/proguard/lh/k;
...
# 改后
goto :cond_0              # 无条件跳过
```

配合 P1，广告管理器根本不会被构造，倒计时与跳过按钮都不会出现。

脚本：`patcher/patch_splash.py`（自动定位 `e1()` 里的条件跳转）

---

## P3 · 空炮 init

Provider 只能断掉"自动初始化"，有些 SDK 会被业务代码主动调 `init`。直接在 SDK 入口把方法打成空返回：

```smali
# com/kwad/sdk/api/KsAdSDK.smali
.method public static declared-synchronized init(Landroid/content/Context;Lcom/kwad/sdk/api/SdkConfig;)Z
    .locals 7
    const/4 v6, 0x0
    return v6
    ...（原逻辑成为死代码）

# com/bytedance/sdk/openadsdk/TTAdSdk.smali
.method public static init(Landroid/content/Context;Lcom/bytedance/sdk/openadsdk/TTAdConfig;)Z
    .locals 1
    const/4 v0, 0x0
    return v0
```

返回 `false` 比 `return-void` 更安全：调用方通常有 `if (init()) {...}` 判断，false 会走"初始化失败"分支，不会继续用未初始化的 SDK。

脚本：`patcher/patch_sdk_init.py`

---

## P4 · 关掉升级弹窗

App 自己的 `UpdateDialog` 被 R8 混淆进了 bytedance 命名空间（`com.bytedance.sdk.commonsdk.biz.proguard.y2.a`），
入口是一个静态方法：

```smali
.method public static update(Landroid/content/Context;Lcom/zdtc/ue/school/model/net/VersionBean;Z)V
    .locals 3
    return-void
```

**坑**：只关 `update()` 会崩。因为 Application 里还会调 `TTAdSdk.start()`，
而 `init` 已经返回 false，`start()` 抛 `IllegalArgumentException: TTAdConfig is null`。
所以 `TTAdSdk.start()` 必须一起置空：

```smali
.method public static start(Lcom/bytedance/sdk/openadsdk/TTAdSdk$Callback;)V
    .locals 3
    return-void
```

脚本：`patcher/patch_update.py` + `patcher/patch_sdk_init.py`

## 验证方法

```bash
# 1. 冷启动，看有没有 SDK 初始化日志
adb logcat -c && adb shell am start -n com.zdtc.ue.school/.ui.activity.SplashActivity
adb logcat -d | grep -icE "openadsdk|mobads|kwad|beizi|pangle"

# 2. 看开屏是否直接进主界面（无倒计时）
# 3. 看首页信息流有没有广告卡
# 4. 扫码 → 下单 → 设备使用 全链路回归
```

## 未解决

快手 SDK 有动态插件加载器，启动时仍会下载 `com.kwad.components.tachikoma` 等插件 dex。init 已经返回 false，但插件更新发生在更早的引导阶段（`PluginUpdaterImpl`），需要在 `KsAdSDK` 的 `<clinit>` 或 `loader` 层再断一刀。当前状态：广告位加载失败，但仍有流量消耗。
